# Spirits Wiki

Private, offline-capable wiki for the Spirits fictional world. Automatically generates wiki pages from `.docx` source documents with **source fidelity** — all wiki content is extracted verbatim from source materials, never generated by AI.

## Features

- **Automatic Wiki Generation** — Parse `.docx` files to extract entities (characters, locations, events, etc.) and generate wiki pages with verbatim source text
- **Source Fidelity** — LLM is used only for classification/routing; all wiki page content comes directly from source documents
- **Editable Pages** — In-browser Markdown editor with immediate database persistence
- **Version History** — Full version tracking with diff view and restore capability
- **Conflict Resolution** — When re-ingesting documents over manually edited pages, conflicts are flagged for user review
- **Image Support** — Images extracted from `.docx` files and manual upload, displayed in Fandom-style infoboxes
- **Q&A System (RAG)** — Natural language questions answered with citations from source documents and wiki pages
- **Private Access** — Password-protected, no public access

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Frontend | Next.js 14 (App Router) + React 18 + Tailwind CSS |
| Database | Neon (serverless PostgreSQL) |
| Vector Store | pgvector (PostgreSQL extension on Neon) |
| LLM | Groq (Llama 3.3 70B) — classification + Q&A |
| Embeddings | sentence-transformers (all-MiniLM-L6-v2) |
| Image Storage | Vercel Blob |
| Auth | NextAuth.js (password-based) |
| Hosting | Vercel |

## Setup

### 1. Prerequisites

- Node.js 18+
- Python 3.10+
- A [Neon](https://neon.tech) PostgreSQL database (free tier)
- A [Groq](https://console.groq.com) API key (free tier)
- A [Vercel](https://vercel.com) account (free tier)

### 2. Environment Variables

Copy `.env.example` to `.env.local` and fill in the values:

```bash
cp .env.example .env.local
```

### 3. Install Dependencies

```bash
npm install
pip install -r scripts/requirements.txt
```

### 4. Database Setup

```bash
npx prisma db push
```

This creates all tables in your Neon database.

### 5. Ingest Documents

Place your `.docx` files in `wikiInitializationDocuments/`, then:

```bash
# Set environment variables
export DATABASE_URL="your-neon-connection-string"
export GROQ_API_KEY="your-groq-api-key"

# Run ingestion
python scripts/ingest.py

# Build the Q&A vector index
python scripts/rebuild_index.py
```

### 6. Run Locally

```bash
npm run dev
```

Visit `http://localhost:3000` and log in with your `WIKI_PASSWORD`.

### 7. Deploy to Vercel

```bash
vercel deploy --prod
```

Set all environment variables in Vercel's dashboard.

## Operator Guide

### Ingesting New Documents

```bash
# Add new .docx files, then:
python scripts/ingest.py --file path/to/new_document.docx

# Rebuild Q&A index to include new content
python scripts/rebuild_index.py
```

### Rebuilding the Q&A Index

After edits or new document ingestion:

```bash
python scripts/rebuild_index.py
```

This rebuilds the vector index **without affecting any wiki content or edit history**.

### Exporting Data

Use the Admin page or API:
- JSON export: `GET /api/export?format=json`
- Markdown export: `GET /api/export?format=markdown`

### Persistence Verification

After any redeployment, verify:
1. All wiki pages are present and unchanged
2. Manual edits are preserved
3. Version history is intact
4. Q&A answers still work

All data lives in Neon PostgreSQL — nothing is stored on Vercel's filesystem.

## Source Fidelity Guarantee

All content on wiki pages is extracted **verbatim** from `.docx` files. The LLM:
- **DOES**: Classify entities, route text to sections, identify cross-references
- **DOES NOT**: Write, paraphrase, summarize, or generate any wiki page content

The Q&A system is exempt — it may synthesize and reason freely to answer questions.
